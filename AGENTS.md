# open_daycare

Daycare management web app (UI copy in Spanish). Early stage: `app/` is still the `create-next-app` default; real screens are built one-by-one against the HTML mockups in `references/pantallas/`.

## Toolchain

- Next.js **16.3.0** + React **19.2.8**, App Router, TypeScript `strict` + `noEmit`, Tailwind **v4** via `@tailwindcss/postcss` (configured in `postcss.config.mjs`, imported in `app/globals.css`).
- Single package (no monorepo). Path alias `@/*` → repo root. Entrypoints: `app/layout.tsx`, `app/page.tsx`.

## Commands

- `npm run dev` – dev server. Also **regenerates the `<!-- BEGIN:nextjs-agent-rules -->` block above**; commit the resulting change to keep the tree clean.
- `npm run build` / `npm start` – prod build & serve.
- `npm run lint` – ESLint flat config (`eslint-config-next` core-web-vitals + typescript). Note: script is `eslint` (no path arg) — runs on the whole repo per config ignores.
- Typecheck: `npx tsc --noEmit` (no script defined; `tsconfig` already has `noEmit: true`).
- No test framework is configured.

## Design references (source of truth for screens)

`references/pantallas/*.dc.html` are self-contained HTML mockups of every target screen; `references/screenshots/*.png` are captured renderings. **Consult the matching mockup before building a screen** — they define layout, components, and copy. Current mockups: `index`, `login`, `activar-cuenta`, `feed`, `crear-publicacion`, `detalle-publicacion`, `avisos`, `ninos`, `agregar-nino`, `perfil-nino`, `resumen-dia`, `foto`, `mi-cuenta`, `familia-feed`, `familia-cuenta`, `vincular-padre`.

`references/pantallas/support.js` is **generated by `dc-runtime` — never edit by hand.**

Design tokens to mirror (verified in mockups): warm cream background `#f6ecdf`, brown text `#3f362e`, coral accent `#f2a78e`; fonts **Fredoka** (display) + **Nunito** (body). Note: `app/globals.css` still holds the `create-next-app` Geist/Arial defaults — it has not yet been ported to the daycare tokens, so expect to update it when building the first real screen.

## Workflow notes

- Playwright MCP is enabled (`opencode.json`). All screenshots/output go under `.playwright-mcp/`. Use it to visually verify pages against `references/screenshots/*.png` after building.
- `spec` and `spec-impl` skills are installed under `.agents/skills/` (see `skills-lock.json`) for spec-driven feature work.
